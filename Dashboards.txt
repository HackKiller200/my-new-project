# Grafana + Loki: datasource and Kubernetes Logging dashboards



## Цель



Настроить Grafana для работы с Loki и создать единое пространство с Kubernetes-логами.



В результате должна получиться структура:



```text

Kubernetes Logging

├── 01 — Kubernetes Logs Overview

├── 02 — Errors & Warnings

├── 03 — Namespace Overview

├── 04 — Pod & Container Drilldown

├── 05 — Nodes Logging

└── 06 — Loki & Promtail Health

```



Используемая схема:



```text

Kubernetes Pods

       ↓

    Promtail

       ↓

      Loki

       ↓

    Grafana

```



Loki развёрнут в `SingleBinary`-режиме и доступен внутри Kubernetes по:



```text

http://loki:3100

```



Promtail отправляет логи в:



```text

http://loki:3100/loki/api/v1/push

```



Grafana должна использовать только базовый адрес:



```text

http://loki:3100

```



---



# 1. Настройка Loki datasource



## 1.1 Открыть настройки datasource



В Grafana:



```text

Connections

→ Data sources

```



Если Loki datasource уже существует:



```text

Connections

→ Data sources

→ Loki

```



Если datasource ещё нет:



```text

Connections

→ Add new connection

→ Loki

→ Add new data source

```



---



## 1.2 Основные параметры



Указать:



```text

Name:

Loki

```



URL:



```text

http://loki:3100

```



Не использовать:



```text

http://loki:3100/loki/api/v1/push

```



Этот endpoint используется Promtail для отправки логов.



Grafana использует base URL Loki.



---



## 1.3 Authentication



Loki используется с:



```yaml

auth_enabled: false

```



Поэтому оставить выключенными:



```text

Basic authentication

OAuth

Forward OAuth identity

Custom HTTP authentication

```



Логин и пароль не требуются.



---



## 1.4 TLS



Так как используется:



```text

http://loki:3100

```



TLS не используется.



Поэтому:



```text

Skip TLS verify = OFF

```



Также не требуется настройка:



```text

CA certificate

Client certificate

Client key

```



---



## 1.5 Проверка datasource



Прокрутить страницу вниз.



Нажать:



```text

Save & test

```



Ожидаемый результат:



```text

Data source successfully connected

```



или аналогичное сообщение об успешном подключении.



Если тест прошёл — Grafana может обращаться к Loki.



---



# 2. Проверка логов через Explore



После успешного `Save & test` открыть:



```text

Explore

```



Сверху выбрать datasource:



```text

Loki

```



В редакторе запроса выбрать:



```text

Code

```



если сейчас активен:



```text

Builder

```



В поле запроса вставить:



```logql

{namespace=~".+"}

```



Нажать:



```text

Run query

```



или:



```text

Shift + Enter

```



Если Loki получает Kubernetes-логи, в нижней части страницы появятся записи.



Например:



```text

2026-09-20 ... monitoring/loki ...

2026-09-20 ... monitoring/grafana ...

2026-09-20 ... production/backend ...

```



Если логи появились, цепочка работает полностью:



```text

Promtail

→ Loki

→ Grafana

```


# 7. Как устроен редактор панели



В верхней части находится preview панели.



В нижней части находится редактор запроса:



```text

Query A

```



Рядом будет переключатель:



```text

Builder | Code

```



Для LogQL использовать:



```text

Code

```



Все запросы из этой инструкции вставляются именно сюда:



```text

Panel

→ Query A

→ Code

→ LogQL query

```



Не нужно вставлять их в:



```text

JSON

Transformations

Panel JSON

Dashboard settings

```

# 23. Обновление LogQL после создания variables



Теперь существующие запросы можно сделать динамическими.



Базовый selector:



```logql

{

  namespace=~"${namespace:regex}",

  node_name=~"${node_name:regex}",

  pod=~"${pod:regex}",

  container=~"${container:regex}"

}

```



Чтобы изменить существующую панель:



```text

Dashboard

→ панель

→ меню панели

→ Edit

```



Далее:



```text

Query A

→ Code

```



Заменить старый LogQL новым.
